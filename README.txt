HotelKiosk — киоск само заселения отеля (РОГОВ)
================================================
Дата сборки: 29.10.2026

СОДЕРЖИМОЕ ПАПКИ
----------------
publish\  — ГОТОВОЕ ПРИЛОЖЕНИЕ (запускать отсюда)
           HotelKiosk.UI.exe + все DLL + конфиги + интерфейс (wwwroot)
           Требуется установленный .NET 9 Desktop Runtime.

publish-agent\ — служба мониторинга (необязательно)
           HotelKiosk.LocalAgent — health-check Regula раз в 10 секунд.
           Ставится службой Windows, см. README.md, раздел «Развёртывание».

source\   — исходный код проекта:
           HotelKiosk.sln — открыть в Visual Studio / Rider / VS Code
           src\           — Core, Application, Infrastructure, LocalAgent, UI
           tests\         — 260 юнит/интеграционных тестов
           scripts\       — publish.ps1: сборка publish\ и publish-agent\
           README.md      — полная документация: архитектура, настройки, развёртывание
           BridgeApi.md   — протокол моста WebView2: конверт, действия, коды ошибок

КАК ЗАПУСТИТЬ
-------------
1. publish\HotelKiosk.UI.exe (двойной клик)
2. Приложение СРАЗУ проверит конфигурацию и покажет список незаполненных
   ключей (блокеры — сверху, предупреждения — ниже). Пока не заполнены,
   соответствующие шаги флоу не работают:

   НЕ РАБОТАЕТ (Error)
   - AlfaBankQr:Login / Password — оплата по QR (СБП).
   - Telegram:BotToken / ChatId  — уведомления стойке о сбоях (в т.ч. о
                                  незаписанной карте). Либо заполните, либо
                                  выставьте Telegram:Enabled=false.
   - LogusApi:Login / Password   — поиск брони и заселение.
   - LogusApi:BaseUrl            — адрес WebAPI отеля.
   - AlfaBankQr:PollIntervalSeconds (<=0) — бесконечный опрос оплаты.

   ПРЕДУПРЕЖДЕНИЯ (Warning)
   - LogusApi:PaymentTransactionCode — оплата пройдёт, но не попадёт на folio
                                       брони, потребуется ручная сверка.
   - AlfaBankQr:TestMode=true       — включён тестовый контур банка.
   - CardTerminal:Enabled=false     — оплата только по QR.
   - VisionLine:Token               — мост используется без авторизации.

3. Заполните ключи в publish\appsettings.json (или в appsettings.local.json
   рядом с ним — он перекрывает основной файл):
   - LogusApi:Login / Password
   - LogusApi:PaymentTransactionCode  — код транзакции для постинга оплат
                                       (узнайте в справочнике Logus)
   - AlfaBankQr:Login / Password      — креды эквайринга Альфа-Банка
   - Telegram:BotToken / ChatId
   Шаблон со всеми ключами: publish\appsettings.example.json

   Секреты намеренно пустые в поставляемом appsettings.json — файл не должен
   содержать реальные пароли. Заполняйте локально на киоске.

4. Адреса интеграций:
   - Logus:      http://192.168.99.9:8020/api   (appsettings.local.json)
   - VisionLine:  http://192.168.4.55:27015      (appsettings.json)
   - Regula:      http://localhost:8080/api      (сканер на киоске)

5. Логи: publish\logs\kiosk-ГГГГММДД.log
   Путь и уровень настраиваются секцией Serilog в appsettings.json.
   Путь относительный — отсчитывается от папки приложения.

ПЕРСОНАЛЬНЫЕ ДАННЫЕ
-------------------
Чекпоинт незавершённой сессии (номер паспорта, ФИО, дата рождения) лежит в
%LocalAppData%\HotelKiosk\session.json — папка приватная для учётной записи
киоска.

Хранение двухступенчатое, потому что этот же файл — единственный след
оплаты, за которую гость не получил заселение:

  через 1 час  — ПДн стираются (паспорт, ФИО, дата рождения),
                 след для возврата остаётся;
  ещё через сутки — след удаляется.

В следе остаются: номер брони, номер транзакции, сумма, признак
«требуется возврат» и шаг, на котором остановились. Гостя там уже нет.

Если бронь ждёт возврата — в лог пишется предупреждение с номером
транзакции, чтобы персонал ничего не пропустил.

Фото гостя на диск не сохраняется: кадр идёт из камеры прямо в Regula.

БЕЗОПАСНОСТЬ ОКНА
------------------
Окно киоска замкнуто на его собственной странице: уход на внешний адрес
отменяется, посторонние окна запрещены, а сообщения в мост принимаются
только от kiosk.html и его картинок.

Проверить можно так: открыть консоль и выполнить
   window.location='https://example.com'
Кик должен вернуться к интерфейсу, а в logs\kiosk-*.log появится запись
«Заблокирована навигация на внешний адрес».

ОДИН ЭКЗЕМПЛЯР
---------------
Киоск работает в единственном экземпляре: повторный запуск просто поднимает
уже открытое окно.

ДИАГНОСТИКА КИОСКА
------------------
Проверка всех интеграций без гостя, отчёт можно унести на стойку:

   publish\HotelKiosk.UI.exe --selftest
   publish\HotelKiosk.UI.exe --selftest C:\temp\отчёт.txt

Окно гостя не открывается, диалог настройки не показывается. Отчёт по
умолчанию сохраняется рядом с приложением: selftest-ГГГГММДД-ЧЧММСС.txt

Отчёт показывает: живость PMS, Regula и VisionLine; какие операции
поддерживает подключённая PMS; для универсальной PMS — весь описанный
контракт (URL, методы, пути в ответе); и список незаполненных ключей
конфигурации.

ВЫБОР PMS
---------
Киоск работает с PMS через единый порт и не привязан к Logus.
В appsettings.json, секция Pms:

   "Pms": { "Provider": "logus", "DisplayName": "Logus" }

- Provider = "logus"   — боевой адаптер, контракт сверен с живым API.
- Provider = "generic" — универсальный HTTP/JSON для любой PMS:
                         Shelter, 1С:Отель, WinHotel и т.п.

Для "generic" заполните секцию "Pms:Generic": адрес, логин/пароль или токен,
а для каждой операции — URL и пути в ответе. Всё, что PMS не умеет, просто
не описывается: киоск скажет «PMS не поддерживает», а не получит ошибку.

Обязательны только поиск брони (Authenticate) и заселение (CheckIn): без них
заселение невозможно, и киоск покажет это как блокер при старте.

Примеры отключаемых возможностей:
- не описали Arrivals — кнопка «Сегодня заезжают» не показывается;
- не описали UpsertGuest — паспортные данные в PMS не уйдут, заселение
  продолжит работать, персонал внесёт их вручную.

Подробный образец с комментариями: source\pms-generic.sample.json.

ДОСТУПНЫЕ ВОЗМОЖНОСТИ
---------------------
ФЛОУ КИОСКА (кратко)
--------------------
Поиск брони: код+фамилия ИЛИ кнопка «Сегодня заезжают» (гость без кода
брони ищет себя по фамилии) ->
фото гостя с паспортом в руках (фронтальная камера, рамка на экране) ->
распознавание паспорта (Regula) ->
оплата: QR (СБП, Альфа-Банк) либо картой через локальный агент пинпада ->
[оплата подтверждена] -> постинг оплаты в PMS ->
заселение в PMS -> запись ключ-карты (VisionLine).
Ключ НЕ пишется без подтверждённых брони и оплаты.

ПРОВЕРКА КАМЕРЫ
--------------
   publish\HotelKiosk.UI.exe --cameratest

Отдельное окно: живое превью, кнопки «Снять кадр» и «Замерить кадр».
Работает без PMS, банка и Regula — проверяется только камера.
Результат пишется в publish\cameratest-result.json.

Что смотреть в отчёте:
- state: open — камера открылась; error:* — смотрите reason
- width/height — фактическое разрешение (задаётся Regula:CameraWidth/Height)
- luma — яркость кадра, ниже 12 = слишком темно
- contrast — контраст, ниже 6 = перед камерой никого нет
- bytes — размер кадра в base64, уходит в Regula как есть

Проверять так:
- Убедитесь, что камера видна в диспетчере устройств и статус «ОК».
- Если state=error:NotAllowedError — разрешение не дошло, проверьте настройки
  приватности Windows для WebView2.
- Если luma низкая — добавьте света или снимите крышку объектива.
- Если контраст низкий — перед камерой пусто, встаньте в кадр.

ПРОВЕРКИ ПЕРЕД ЗАСЕЛЕНИЕМ
-------------------------
Заселение в PMS не проходит, пока не подтверждены:
- бронь найдена;
- оплата подтверждена у банка/пинпада (при сумме больше нуля; бесплатное
  проживание — комплимент, трансфер — оплаты не требует);
- для записи ключа: гость уже заселён.

Статус оплаты спрашивается у банка или терминала, а не берётся из экрана.
Если оплата не подтверждена, гость видит «обратитесь к администратору» —
повторять бессмысленно, деньги от этого не появятся.

ЧТО ПРОИСХОДИТ ПРИ СБОЕ
-----------------------
- Отмена до оплаты      — QR-заказ отменяется у банка, денег нет.
- Отмена ПОСЛЕ оплаты  — возврат выполняется автоматически.
- Статус платежа неизвестен — ничего не делается, зовётся персонал
                         (ошибка в любую сторону ударит по гостю).
- PMS не заселил        — персонал разбирает вручную.
- Карта не записалась  — возврат НЕ делается (гость уже заселён),
                         персонал выдаёт карту вручную.
- Гость ушёл, не оплатив — QR-заказ просто истечёт, возврат не требуется.
- Процесс упал / выключили ПК — при следующем запуске киоск покажет
                         незавершённую сессию с номером транзакции.

Важно: чекпоинт различает «заказ создан» и «деньги списаны». Если гость
ушёл, не оплатив QR, запись сохранится для разбора, но помечаться как
«требуется возврат» не будет — иначе персонал искал бы деньги, которых
никто не платил.

Фоновый опрос оплаты следит за тем заказом, который запустил его, даже
если гость успел переключиться на другой способ оплаты.

Сессия гостя закрывается после успешного заселения или отмены: оплата,
паспорт и бронь обнуляются. Брошенная сессия не достанется следующему
гостю — поиск новой брони её сбрасывает.

СКАНИРОВАНИЕ ПАСПОРТА
--------------------
Схема по умолчанию: гость встаёт в рамку и держит открытый паспорт рядом с
лицом, камера снимает кадр, он уходит в Regula на OCR. Физический
считыватель не нужен, ключ Regula:AgentScanPath можно оставить пустым.

Настройки (publish\appsettings.json, секция Regula):
- CaptureSource          "camera" (по умолчанию) | "reader"
- CameraWidth/Height     1280 / 960 — размер кадра для OCR
- CameraJpegQuality      0.9 (ниже 0.6 MRZ читается нестабильно)
- CameraCountdownSeconds 3 — отсчёт до съёмки

Разрешение на камеру выдаётся автоматически. Если камера подключена к
другому USB-порту или её видно в диспетчере устройств как отключённая —
проверьте её до запуска киоска.

Тайминги оплаты (AlfaBankQr:PollIntervalSeconds, QrLifetimeMinutes,
CardTerminal:PollIntervalSeconds) реально применяются — и в бэкенде, и в
интерфейсе: приложение передаёт их в kiosk.html при старте.

Демо-режим (без бэкенда, все действия мокаются):
   publish\HotelKiosk.UI.exe --demo
